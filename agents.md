# Mobile UX/UI guidance

When designing mobile interfaces, use the best qualities of Apple Watch: fast comprehension, calm hierarchy, and confident interaction.

- Design for a glance first. Put the current status, most important result, and next action above the fold; remove anything that does not help the user decide or act.
- Make one primary action obvious per screen. Keep secondary actions discoverable but visually quiet, and use progressive disclosure for detail and configuration.
- Use short labels, familiar symbols, and plain language. Never make an icon carry an important meaning without a text or accessible label.
- Prefer focused flows over dense dashboards. Break complex tasks into small, reversible steps and preserve the user’s progress when navigating back or losing connectivity.
- Make touch interaction forgiving: provide generous hit areas, clear pressed/focused states, spacing between destructive actions, and avoid edge or gesture conflicts.
- Respect mobile context. Support one-handed use, variable screen sizes, portrait and landscape where useful, reduced motion, dynamic text sizing, dark mode, and high-contrast needs.
- Give immediate feedback. Pair visible state changes with appropriate loading, success, empty, offline, and error states; use haptics or sound only when useful and never as the sole feedback channel.
- Keep motion purposeful and brief. Use transitions to explain hierarchy or continuity, not decoration; preserve the user’s sense of place when content changes.
- Favor glanceable components: clear typography, strong contrast, restrained color, compact status indicators, and information grouped into scannable rows or cards.
- Treat notifications as interruptions with a budget. Show only timely, actionable information and make the destination and next step explicit.
- Design resiliently for slow networks and interruption. Show useful cached content, communicate freshness, avoid layout jumps, and make retry safe.
- Validate accessibility and ergonomics before polish: VoiceOver/TalkBack labels and order, keyboard/switch access where applicable, contrast, text scaling, target sizes, and screen-reader announcements.
- Do not shrink a desktop UI onto a phone. Start with the smallest practical viewport, prioritize the core journey, then progressively enhance for larger screens.
